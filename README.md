# 비밀번호 보안 도구 (`26-w12-password`)

> 이 README는 실습을 완성한 뒤, 배포 직전 단계에서 직접 채워 넣습니다.
> 실습 안내와 완성 기준은 [`guide.md`](./guide.md)를 참고하세요.

## 소개

`crypto.getRandomValues()` 기반 안전한 비밀번호 생성과 실시간 강도 평가를 한곳에 모은 비밀번호 점검 대시보드입니다.
브라우저에서 SHA-1 해시를 만든 뒤 앞 5글자만 HIBP API에 조회하는 k-익명성 방식을 적용해 원문 노출 없이 유출 여부를 확인할 수 있습니다.
라이트/다크 모드 전환 기능까지 더해 실제 점검과 생성을 간편하게 다루도록 구성했습니다.

## 보안 점검 (사이버보안과 체크포인트)

1. 비밀번호 생성에 Math.random() 대신 crypto.getRandomValues()를 써야 하는 이유는 무엇인가요?
   - `Math.random()`은 암호학적으로 안전한 난수 생성기(CSPRNG)가 아니므로 예측 가능성이 있을 수 있는 반면, `crypto.getRandomValues()`는 운영체제/브라우저의 암호학적 난수 소스를 활용해 보안 민감한 값 생성에 더 적합하기 때문입니다.

2. 유출 확인 시 Network 탭에서 확인한 실제 요청 주소를 그대로 적어 주세요. (예: https://api.pwnedpasswords.com/range/XXXXX)
   비밀번호나 전체 해시가 전송되지 않았나요?
   - `https://api.pwnedpasswords.com/range/XXXXX` (※ 브라우저 F12 Network 탭에서 실제 요청된 앞 5자리 대문자 해시로 교체해 적어 주세요.) 비밀번호 원문이나 SHA-1 전체 해시는 외부 서버로 전송되지 않았습니다.

3. k-익명성 방식으로도 서버가 알 수 있는 정보는 무엇인가요? (완전한 익명이 아닌 이유)
   - 요청이 들어온 시점의 IP 주소 등 네트워크 메타데이터와, 전송된 SHA-1 해시 앞 5자리(`prefix`)에 해당하는 조회 요청이 발생했다는 사실은 서버 측에서 인지할 수 있습니다.
